## Design and findings

- Keep the film format and scene sample schedule together as domain data.
  - Compose owns 960×540, 12 fps, 12 seconds, while decode independently assumes
    144 frames and verify repeats that assumption for decode evidence.
  - Render, decode and verify each copy sample frames 9, 60, 108. These represent
    the same reviewed scene times and must change together if the rate changes.
  - Decode hardcodes dimensions and duration even though render uses manifest
    values. The verifier should compare decode evidence with that same manifest.
  - The composition template itself is deliberately fixed to three four-second
    scenes. Keep its runtime and committed generated bytes unchanged; use that
    format as the composition defaults, while media consumers read the manifest.
- Add the missing production build to CI after behavioral/media checks, so the
  React player integration is compiled before merge. Keep expensive work serial.
- Preserve repository-specific curation (delivery-dash map, shortened Mantine
  example, Garmin release block, protected trading wording, source screenshot
  allowlist). These are editorial/privacy requirements, not generic exceptions.
- Preserve serial provider/media processing, browser software-GPU settings,
  operation deadlines and exclusive render lock: external resource constraints.
- Preserve minimal output and sequential execution helpers: lint policy and the
  one-operation-at-a-time contract justify these boundaries.
- Preserve missing-input failures for trusted capture evidence. Do not fabricate
  capture data or refresh source/media as part of this refactor.
- Preserve behavioral tests (escaping, protected screenshots, evidence ownership,
  deterministic capture, scene backgrounds, serial order/failure). None is
  demonstrably worthless; do not delete assertions for cosmetic simplification.
- Keep comments describing external capture/privacy constraints and curation
  schema. No standalone comment merely restating an operation needs removal.
- Leave byte-range serving and playback structure alone: no structural evidence
  warrants replacing the existing service or splitting the small React view.

### Review round 1

Independent whole-repository static review identified three additional evidence
contracts worth fixing before merge:

- New reports still stamp the original engine/encoder versions after dependency
  upgrades. Read installed package metadata for new reports; preserve historical
  evidence unchanged. Node filesystem/crypto APIs cover this glue; no dependency
  or custom executable script is needed.
- Decode checks count samples but do not verify their frame identities. Compare
  frame identities with the common scene schedule, rejecting stale evidence.
- Compose matches screenshot metadata by source SHA but trusts the PNG filename.
  Check its bytes against the recorded screenshot SHA-256 before embedding.
  A behavioral test must reject replacement bytes with unchanged metadata.
